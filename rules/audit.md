# 征地拆迁审核通用实审方法

> 本文件只写可迁移的实审方法、证据要求和边界，不写具体项目政策、单价、比例、地名、对象编号、金额或结论。
> 同目录格式见 `format.md`，意见句式见 `../catalog/opinions.md`，工具用法见 `../docs/tools.md`，流程与交接见 `../workflow.md`。
> 项目固定口径（测绘签章条、取位习惯、表名与路径约定）不写入本文件，由项目本地规则补充，不外推为通用政策。

## 0 三条底线

1. **结论只写证据支持的内容。** 每条事实结论都要能回到具体文件、物理页或单元格、对象编号和原值；推断、经验、历史相似只作线索。
2. **未知不写 0。** 待核的采用额与调整额留空（null），已知涉及额单列；不得用 0、全额或空白冒充结论。
3. **打开、搜索、识别、计算、工具 PASS 都不等于业务已核。** 只有实际回源看过内容、逐项对照过依据，才算该项已核。

## 1 锁定范围与版本

开始前写清并在底稿固定：

| 项 | 要求 |
|---|---|
| 批次与阶段 | 批次全称、初审／请款／结算、类别范围、明确不审的类别 |
| 对象与目的 | 审哪些宗地／户／墓／房屋／费用，出什么结论 |
| 输入版本 | 每份原件的路径、哈希、物理页数或表页、可读性；同名不同内容分别登记 |
| 时点与依据 | 征收时点、政策版本、项目执行依据；历史单价与旧意见不作当前依据 |
| 输出位置 | 成果、内部底稿、临时文件各自位置；原件只读、成果另存 |

- 相同内容副本按哈希去重，但保留全部路径与提交关系；文件重复不等于费用重计。
- 一个输入版本对应一个运行记录；原件版本变化时只暂停受影响批次，其余继续。
- 用户当前范围、格式要求和手工修改优先于任何模板或旧规则。

## 2 全原页、全行枚举

先枚举原始载体上的全部业务行，再与电子表匹配。**不得按电子表反筛原页**，否则会漏掉只在原页存在的对象。

| 载体 | 必须枚举的内容 |
|---|---|
| 扫描页／图页 | 全部物理页，含空白页、签字页、附件页、续页；手写增补、划销、涂改、重叠标记、页边批注、骑缝与印章 |
| 电子表 | 全部工作表（含隐藏、veryHidden）、隐藏行列、筛选外行、合并单元格、公式与缓存、批注、嵌入图片、独立附表 |
| 压缩包 | 目录条目、分卷、同名文件、非业务附件、加密或损坏文件 |
| 交接清单 | 收件记录与实际文件逐一对应；清单有而文件无、文件有而清单无都要记 |

每行至少保留：`raw_row_id`、来源与物理页／表页／单元格、`object_id`、`fee_id`、原文、标记状态（清晰／空白／不存在／划销／改写／不可读）、读取状态。

- 划销、改写、不可读的行**保留在分母内**，写明原值、改值和辨认程度；不能因为"看起来作废"就删行。
- 续页、无编号续行、只在页边补写的对象单独建行，并注明与父行的关系。
- 空白页也要回看确认；"没识别到文字"不能证明该页空白或无关。
- 电子表公式缓存为空不是 0；缺缓存只在副本重算，不替原稿造缓存。

## 3 双向映射与 1:N

映射键优先用**对象编号＋费用类别＋规格／部位＋出现次序**；姓名只作比较字段，不作唯一键。地号、墓号、建筑物编号、迁坟编号要分清，不能用宗地号代替墓号。

必须同时做两个方向：

1. **原页 → 电子表**：每个原始业务行指出对应的电子行，或标注未列入、未采用、明确排除、待确认。
2. **电子表 → 原页**：每个电子行指出来源原页或原表，独立附表、追加行同样要回源。

允许并必须解释一对多、多对一：

- 一户多品种、一宗多地类、一墓多穴、一层多部位，按实际粒度拆子行后再比较，不能拿整户合计直接对单宗费用。
- 汇总行、父项、小计只作关系节点，不新增费用；先查独立费用表是否已包含在主表内，避免重复加总。
- 分摊或汇总要有公式或文字依据；"总额吻合"不能消除逐行差异。
- 未匹配、同键多行、字段冲突分别记为候选，不强行配对、不按姓名猜。

### 示例（只用关系占位符）

```text
对象：【宗地A】｜类别：土地｜规格：耕地｜出现次序：1
原页行：物理P3 第5行｜权利人：【权利人A】｜面积：0.0000｜金额：0.00
电子行：明细!D12｜权利人：【权利人A】｜面积：0.0000｜金额：0.00
关系：1:1｜差异：面积字段不一致｜处置：DEFER（待回原页确认改值）
```

涉及领款关系时用【收款人B】表示与【权利人A】不同的收款主体，并在底稿写清授权或权属依据；公开示例不出现真实姓名、账号或地址。

## 4 差异闭环

每个差异一条记录，字段固定：两侧原值、各自文件与页／格、对象编号、差异性质、原因、适用依据、处置结论、复核人与轮次。

处置只有三类：

| 处置 | 含义 | 关闭条件 |
|---|---|---|
| RESOLVED | 已按证据改正或确认一致 | 两侧原值与改正后值都可回查 |
| EXPLAINED | 差异真实但已完整解释 | 解释对应实际证据，不是"以某路为准" |
| DEFER | 仍未解决 | 保持开放，列明缺什么、谁补、下一步 |

- 手写、划销、涂改要回原页核对具体文字、签认身份与日期、修改顺序，再判断有效申报版本；不能默认打印稿或最后可见笔迹生效。
- 不能只写"以审核表为准""以扫描件为准"；未解释的差异保持开放。
- 来源或任一侧台账变化后，旧处置失效，需重新核对。
- 差异数量不代替覆盖：已处置多少条、还有多少条开放，要能数出来。

## 5 政策适用与 PENDING

政策逐项登记为 **APPLICABLE／PENDING／NOT_APPLICABLE**，并记录检索词、检索位置、找到或未找到。

- 逐费用核实：发文机关与文号、适用区域与区片、施行与过渡时点、补偿对象与类别、计量单位、标准条件、上下限、包含与排除项、项目采用依据。
- 政策在库、数值吻合、历史意见引用过，都不等于本项目适用；必须回到原文条款及附表。
- 原文冲突时列两处原文及影响，不自行取高、取低或取平均；不把其他地区标准移用。
- 缺依据只阻断相应政策或金额结论，其余对象继续；不能因一份政策缺原件就停整批。
- PENDING 的采用额和调整额为 null，已知待核涉及额单列，并写明影响哪些费用。
- 不机械要求"转发文"；但要说明何种依据支持直接适用。

## 6 分类实证要点

### 6.1 土地与红线图

- 明细到图、图到明细双向核；可先按地号搜索，再用姓名、面积辅助定位。
- 图片页先渲染或 OCR 定位，**必须回看原图**确认；每宗留图号、物理页、可辨认截图索引。
- 搜索无结果只记"未定位"；只有地号命中不算已核红线。
- 核编号、权利人、地类分项面积、总面积、红线内外面积闭合、图幅版本、坐标系与比例尺、出图与签章。
- 图件或成果报告缺签章的，按项目出稿口径提出补盖；是否影响结论按项目规则，不自行推定无效。

### 6.2 道路、坑塘、建设用地与青苗

1. 先从明细枚举全部建设用地、其他农用地，以及按全宗面积申报青苗的地块。即使当前行没有青苗金额，也核该地类面积是否计入同宗其他行的青苗补偿。
2. 用地号、姓名及分项面积对应批次红线图。批次图仅写大类、标注不清或与表不一致时，回查全线土地丈量图。记录实际标注，如公路用地、农村道路、沟渠、养殖坑塘、农村宅基地。图件仍不能确定时，保留待核。
3. 每宗记录图件名称与物理页、具体地类及面积、申报青苗面积与金额。两份图件的面积、地类或权利人有差异时，记录两个原值与版本，核实应采用的测绘成果。
4. 全面积申报时，查实际种植、清点或计补依据。待核金额留空，保留送审金额。青苗款是否写入协议及协议金额与计算表是否一致，单独核。

### 6.3 竹果木

- 核树种、规格、计量单位、清点数量、种植面积、密度上限、套种关系、与基础青苗是否重复包含。
- 先按适用规则算"面积×上限"，再核数量取整或四舍五入，最后判断是否超量；小数尾差不能直接列超标。
- 逐类核单位；输出数量合计可按用户习惯直接求和，但混合单位的总数不得用于密度复算。
- 规格档位与单价要对应本批依据；汇总表标准栏空白不等于无标准，也不等于可套旧价。

### 6.4 鱼塘

- 核实际水面、征收范围、塘体与塘埂等分项，登记面积与图面面积是否一致。
- 核承包与收益权、搬迁标准、设施是否重复计补；先查主表是否已包含，再决定是否单列。
- 输出可归入青苗或鱼塘搬迁栏目，实质核查仍按费用分别列示。

### 6.5 房屋、构建筑物、附属物

- 按户—幢—层—部位核结构、用途、檐高、尺寸、数量和单位；"所在楼层"与"建筑总层数"是两个字段。
- 丈量图、清点表、照片、明细相互核对；建筑面积与占地面积、阳台／挑廊／平台折算分开。
- 原表已折算的不得再次折算；先辨认列义和计算过程，再套规则。
- 围墙、地坪、井、池等独立计量；父项汇总不能再次作为新增费用。
- 临时安置、搬迁、经营损失核资格、人数或面积、期间、计算方式与重叠补偿；只有汇总金额的先保留送审，不伪造数量和标准。

### 6.6 坟墓迁移

- 墓号与宗地号分列，逐墓核编号、管理人、坐落、对应宗地、墓型、穴数与单价。
- 登记—现场清点—照片持牌—红线图—协议双向核；不能因找到宗地号就算找到墓号。
- 图中逐个确认墓位与红线范围；未标墓位或图像不清记待核。
- 照片核标牌、管理人持证与证件原页，不凭文件名推定一致。
- 查一墓多穴、多墓同人、重复编号、同墓重复申报；不以总穴数吻合代替逐墓对应。
- 图面点位与表内墓号双向清点；图上有标注而表内无记录、表内有申报而图上无点位，分别记录并说明编号去向。

### 6.7 主体、签认、身份与账户

- 集体经济组织核完整名称、村组层级与登记证明一致；个人、集体、承包人、青苗／附着物权利人和领款人分别核。
- 差异查权属协议、授权或决议；不能因表内合行就抹去差异。
- 核签字、指印、盖章、日期、代理权限与阶段适用要求；申请／支付阶段判断应有凭证，不要求尚未发生的付款凭证。
- 实际打开身份证、银行卡扫描件，逐人核姓名、号码、户名、账号与授权；**校验位通过不等于看过证件**。
- 身份号码、联系电话等登记值在不同载体间不一致时，只记两处位置与原值并写"两者不一致"；不判断哪一份为准，不推定抄错、代填或真伪。
- 公开参考库和公开分享的成果脱敏；本次业务交付按用户授权与必要范围保留核对信息。

## 7 计算、取位与尾差

- 用十进制运算，保留原精度，在有依据的环节舍入到分；浮点累加不作底稿。
- 顺序固定：先核送审输入自身算术，再核原页输入，最后核适用规则下的金额；独立计算不得引用送审合计作为自身输入。
- 送审原值不改；送审汇总与明细不一致也保留差异，不为对平改原值。
- 计算底稿保留：原始输入、来源页格、单位、公式、系数、取位与舍入顺序、申报量、独立量、拟采用量、差异及理由。
- **尾差**：先查明本批送审的取位口径，审核取位按已确认的适用依据；仅取位差先区分计算口径和真实数量差，再决定是否影响采用额。口径本身存疑时记待核，不擅自统一或倒改送审。
- 合计分三层：分项→户→批次；明细、汇总、报告三处金额勾稽，差异定位到行。
- 不同量纲（面积、长度、体积、株、座、穴）分别复算，不跨量纲相加；混合单位合计只作表式合计，不作限额判断。

## 8 收件与实核

收件口径与内容口径必须分开记录：

| 字段 | 取值 | 说明 |
|---|---|---|
| carrier | electronic／scan／both／na／missing／unknown | 电子表、扫描件分别记；两种都提供才 both |
| content_status | confirmed／missing／na／其他 | 只有 confirmed 表示内容已核；暂记 √ 仍属未验证 |
| scope | whole／partial／object | 整批缺失、部分缺失、个别对象缺件分开 |

- √ 只表示"收到该载体"，不证明内容已核或业务合格；附件内常夹身份证、账户、照片，按实际回看后更新。
- × 只用于确认本批应提供而整批缺失的资料，且意见中有对应一条；个别对象缺件写在意见或待核说明，不在表内打 ×。
- 确认不适用标"／"；范围外类别整行隐藏，不删除。
- 数字 PDF 有明确电子表载体时按实际来源记，不能仅因"电脑能打开"就归电子版。
- 载体缺失要写清缺失范围与对应意见原文片段，否则核验工具只能记未验证。

## 9 金额处置与核减边界

| 状态 | 采用额 | 调整额 | 条件 |
|---|---|---|---|
| CONFIRMED | 有值 | 有值 | 事实、适用依据、独立复算、复核同时成立；无未关闭金额问题 |
| PENDING | null | null | 有待核条件；已知涉及额单列 |
| OUT_OF_SCOPE | null | null | 有依据支持本轮范围外；不能借此排除证据不足的范围内项目 |

核减必须有四样东西同时成立：**已确认的事实、适用的依据、可复算的金额、复核记录**。

- 缺协议、缺签字、缺身份、缺政策原件、暂未找到图号，都先记待核，不直接核减。
- 不写"该笔缺少依据"式推论；写两处原值或写缺什么、请补什么。
- 待核费用不能写 0，也不能写全额核减；调整额统一为"采用额−送审额"。
- 同一费用多个问题只计一次金额；问题表金额只引用，不参与汇总。
- 建议与最终审批效力分开表述；AI 初稿不构成行政审定。

## 10 覆盖、完成与未核清单

分别统计、不得互相替代的六类数字：收到文件／页、已渲染或识别、实际已读、已枚举原始行、已双向匹配、已复算。

- 覆盖分母写清楚：应核对象数、已核对象数、未核对象数；类别逐个列，不能用一个类别代表全部。
- 每个对象、每个应查项都要有结果：PASS／FINDING／BLOCKED／NA／NOT_STARTED；BLOCKED 与 NOT_STARTED 不计已完成，NA 要有理由。
- 完成条件：范围内对象与费用无遗漏、应查项有结果或明确未核、金额只汇总一次、采用值有依据和复核、成果从实际保存文件回读、打印与显示已实际查看。
- 未核清单必须点名对象、缺什么、为什么、下一步谁补；不能只写"部分资料待补"。
- 意见条数、文件数量、旧对话结论都不能推定完成。

## 11 交付最小集

| 交付 | 内容 | 备注 |
|---|---|---|
| 补偿审核表 | 汇总＋明细，送审原值、审核公式、核增减、待核状态 | 公式不直接引用送审金额；金额精度按本批依据，母版预设两位小数 |
| 资料符合性核查表 | 按类别逐项记载体与内容状态 | 与意见、底稿口径一致 |
| 审核意见／初审意见 | 一条一个问题，两处原值，请核实或补充 | 写法见 `format.md`，句式见 `../catalog/opinions.md` |
| 内部底稿 | 对象、费用、映射、差异、政策、复算、覆盖、未核 | 不塞进对外表；保留定位与截图索引 |

只制表时明确写"尚未经实质审核"；实审有未决条件时，相应采用额保持待核、合计标明不完整。

## 12 工具证据边界

工具只证明它检查过的那一小块，不证明业务真实、政策适用或权属清楚。

- 读表工具记录原值、公式与缓存，不执行公式；不证明已读扫描件或图。
- 十进制复算工具只证明给定输入的算术一致；输入假设错了，结果仍会"通过"。
- PDF 检查、编号定位、红线叠图只做定位与视觉差异，不计算面积、不判定越界、不认证测绘。
- Office 包对比只列部件变化，不证明业务正确，也不等于宿主实际显示正常。
- 映射检查、成果核验只按显式配置核对金额、公式、载体、覆盖与来源；缺配置即未验证。
- 打印与分页必须在副本上用实际 Office 重算并导出后看页；HTML 预览不能代替。

> 任何工具返回 0 或 PASS，都只写"该工具检查范围内通过"，不写成"审核通过"。
